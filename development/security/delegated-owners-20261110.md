# 最高オーナーとオーナー

既存の settings.owner_id を唯一の最高オーナーとして維持する。ブラウザーから変更・追加するAPIは作らない。最高オーナーのみ、メール確認済み・利用可能な既存アカウントにオーナー権限を付与できる。通常のオーナーは既存のオーナー承認・管理・メンテナンス・復元操作を利用できるが、オーナー追加APIは拒否される。管理者専用パスワードと有効セッションの確認を維持する。

管理者ページ → オーナー専用の操作に追加フォーム。付与操作は削除できない保護履歴に記録。オーナー本人の削除、BAN、管理者解除の既存経路では最高オーナーと通常のオーナーを保護する。今回、オーナー降格・最高オーナー移譲のAPIは追加しない。

検証：PGliteで12項目（偽装確認、不確認メール、通常オーナーの再付与拒否、両オーナーの保護、未認証、匿名権限、監査記録）。既存の管理画面テスト14組合せが成功。本番では一時的な検査アカウント・セッションだけを使い、付与・通常オーナーの再付与拒否・最高オーナー保護をトランザクション内で検査し、全書き込みをROLLBACK。実アカウントの追加・削除・権限変更は行っていない。
