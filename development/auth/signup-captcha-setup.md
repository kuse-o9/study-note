# 新規登録の自作CAPTCHA

対象はメールでの新規登録です。既存ログイン、パスワード再設定、管理者確認を変更しません。足し算は自動化可能なので、強力なボット判定として扱わず、回答回数と発行数の制限、メール確認に重ねます。

本番の初期設定は `signup-captcha.json` の `enabled: false` です。公開側の表示だけを変えても、認証APIへの直接の登録要求は制限できません。

1. 検証用の登録画面で `enabled: true` を使用し、問題が表示され、正しい回答で確認証が得られることを確認する。
2. 本番UIの `enabled` を `true` にして読み戻した後、Supabase → Authentication → Hooks → Before User Created で PostgreSQL の `public.study_signup_guard` を設定する。既存のフックがある場合は上書きせず、既存チェックと統合する。
3. 専用テストメールで確認証なしの登録が拒否され、正しい回答でメール確認まで進めることを確認する。既存アカウントでのログインも確認する。
4. 切り戻しは先にフックを解除し、その後 `enabled: false` に戻す。

期限は発行から3分。回答は1回、発行した確認証は登録時に1回だけ消費できます。回答やメールをフロントに保存せず、期限付きの確認証だけを登録処理に渡します。データベースに残るメールのハッシュなどは、次回発行時に15分経過分を削除します。無料プランでは既存アカウントのパスワード認証フックを有効にしません。
